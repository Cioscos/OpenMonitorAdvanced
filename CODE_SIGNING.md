# Code signing policy

OpenMonitor Advanced is a free, open-source hardware monitor for Windows (GPL-3.0-or-later). This
page describes how its Windows binaries are, or will be, signed.

## Status

Code signing is **planned, not active**. The application to the
[SignPath Foundation](https://signpath.org/) has not been submitted yet, so no release is signed
and Windows SmartScreen may warn when you run the installer (see the README). Until the
Foundation approves the project and the first signed release is published, this page states the
policy that will apply; it does not claim that any release is signed.

When signing is active, this page will carry the attribution required by the Foundation and the
README will point to it.

## Roles

| Role | Who |
|---|---|
| Committers and reviewers | [@Cioscos](https://github.com/Cioscos), the owner of the repository |
| Approvers | [@Cioscos](https://github.com/Cioscos) |

Every signing request is approved by hand on SignPath by the approver. Two-factor authentication is
required on GitHub and on SignPath for every role.

## What is signed

Each release is built from a version tag by the GitHub Actions workflow
[`.github/workflows/release.yml`](.github/workflows/release.yml) on a GitHub-hosted runner. Once
signing is active, these files carry the signature:

- the installer (`OpenMonitor Advanced_X.Y.Z_x64-setup.exe`);
- `oma-app.exe`, the application;
- `oma-service.exe`, the optional sensor service;
- `uninstall.exe`, the uninstaller generated by NSIS, so that the Windows confirmation prompt of
  the uninstallation also shows the publisher.

The signed files carry the product name "OpenMonitor Advanced" and the release version. Each
release also ships `SHA256SUMS.txt` and a GitHub build provenance attestation (see the README,
"Verify your download").

## What is not signed

Only our own code is signed. Third-party files are never submitted to SignPath and keep the
signature, or the lack of one, of their authors:

- `PawnIO_setup.exe`, the installer of the [PawnIO](https://pawnio.eu/) driver, bundled
  unchanged and checked against a pinned SHA-256 at build time;
- the NSIS plugin DLLs (`nsExec.dll`, `NSISdl.dll`, `System.dll`, ...), which stay unsigned.

## How to verify a signature

In PowerShell:

```powershell
Get-AuthenticodeSignature -FilePath .\OpenMonitor.Advanced_X.Y.Z_x64-setup.exe |
  Format-List Status, StatusMessage, SignerCertificate, TimeStamperCertificate
```

`Status` must be `Valid` and the signer must be "SignPath Foundation". The same command works for
`oma-app.exe` and `oma-service.exe` in the installation folder (by default
`C:\Program Files\OpenMonitor Advanced`) and for `uninstall.exe`. For the installer you can also
check the checksum and the build attestation as described in the README.

## Privacy

This section describes what we verified in the project's own code, installer and bundled
components. Where a third-party component has its own behavior, we link to its policy instead of
describing it.

- **The application (`oma-app.exe`) and the service (`oma-service.exe`) send no data over the
  network.** The Rust workspace and the service have no HTTP client and no telemetry, and the web
  interface may talk only to the local Tauri bridge (its content security policy allows
  `connect-src ipc: http://ipc.localhost`). The app and the service communicate with each other
  over a local named pipe. The sensor library the service uses, LibreHardwareMonitorLib 0.9.6,
  references no HTTP or socket types, only the local network adapter list
  (`System.Net.NetworkInformation`).
- **Settings, history and the optional CSV log stay on your PC**, in
  `%APPDATA%\OpenMonitorAdvanced` and in the folder you pick for the log. Nothing is uploaded.
- **The interface is rendered by Microsoft Edge WebView2**, which is a Microsoft component with its
  own privacy behavior, outside our control: see the
  [Microsoft Privacy Statement](https://privacy.microsoft.com/privacystatement) and the
  [WebView2 documentation](https://learn.microsoft.com/en-us/microsoft-edge/webview2/).
- **The installer downloads Microsoft's WebView2 bootstrapper only if WebView2 is missing.** We use
  the Tauri default (`downloadBootstrapper`): when no WebView2 runtime is registered, the installer
  fetches the Microsoft bootstrapper from `go.microsoft.com` and runs it. Windows 11 ships the
  runtime, so there the download normally does not happen. The installer downloads nothing else.
- **PawnIO is bundled, not downloaded.** `PawnIO_setup.exe` is inside our installer. It is installed
  only if you keep the *Advanced sensors* component selected. For the driver's own policies see
  [pawnio.eu](https://pawnio.eu/).

The app currently has **no update check**. A planned future release will add one that contacts
GitHub; when it does, this section, the setting to turn it off and the documentation will be
updated before the release.
